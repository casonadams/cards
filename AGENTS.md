# Cards Repository Rules & Standards

## UX & UI Design Rules

### CSS Layering & Tailwind Precedence
- Never define unlayered CSS resets (such as `* { margin: 0; padding: 0; }`) in HTML `<style>` tags or unlayered stylesheets. In CSS Cascade Layers, unlayered declarations override all `@layer utilities` regardless of specificity, breaking Tailwind layout classes.
- Consolidate design tokens inside `@theme` in `app.css`. Do not maintain parallel, conflicting CSS custom properties in `index.html`.

### Card Hand & Fanning Conventions
- In fanned hands with left-to-right stacking (`z-index` increasing left to right), each card overlaps the right edge of the preceding card. Never place penalty or scoring badges on the top-right corner where they get occluded by the next card; render penalty points (such as `10` on hearts or `25` on queens) in the bottom-left corner (`bottom-1.5 left-1.5`). The exposed left rail guarantees 100% visibility while cards are fanned in hand, while leaving the bottom-right corner for the standard inverted rank/suit index and the top-right corner clean and uncluttered.
- Render a bold rank glyph centered on every card in the deck: numerals `2`–`10`, court letters `J`, `Q`, `K`, and `A` on Ace cards (rather than an oversized suit symbol). Do not render faded suit watermarks behind center glyphs; keep card faces clean, high-contrast, and uncluttered.
- Scope hover and focus elevation to playable cards (`.card-hand-slot.is-playable:hover`). Disabled and unplayable cards must remain seated and subdued (no translation).
- Never apply container opacity (`opacity < 1`) to cards in fanned hands. Translucent card backgrounds cause additive overlap brightening (white capsule stripes) and ghosted bleed-through of the underlying card's rotated indices. Unplayable cards must use solid opaque muted backgrounds (e.g. `bg-slate-200 border-slate-300 text-zinc-700`).
- Horizontal scroll containers (`overflow-x-auto`) must not use `mx-auto` or `justify-center` on overflowing children (`w-max`), as CSS centering clips the left edge and prevents scrolling back to initial items. Use `inline-flex min-w-full justify-start sm:justify-center px-4`.
- Hand Container Height Preservation: When a player plays their final card (`myCards.length === 0`), the hand container must never vertically collapse (which previously collapsed 122px, causing parent flex layouts to drop the playing arena downward by ~60px). Maintain a permanent reserved minimum height (`min-h-[130px] sm:min-h-[160px]`) on both the hand wrapper and `HandDisplay`, displaying a quiet centered placeholder (`All cards played`) to ensure zero layout shift when the hand empties.

### In-Table Flow vs Blocking Overlays
- Prefer embedding phase transitions (such as bidding consoles and round-end summaries) directly in the tabletop arena between the trick area and the hand rather than full-screen blackout modals.
- During bidding, keep the player's real hand visible at the bottom of the table with full trump highlights and indices; do not build duplicate hand displays inside detached modals.
- Hand cards during non-playing phases (such as bidding) must remain in a non-interactive inspection state (`inspection={true}`, `playable={false}`, `pointer-events-none`, `disabled`, and `onclick={undefined}`). Players must never be able to click or dispatch card play actions during bidding, which breaks engine round state machines.
- Bidding consoles must explicitly display who bids first and leads trick 1 (`🎯 1st Bid & Lead`) versus who is the dealer (`Dealer (bids last)`), and annotate player bid chips with matching role tags so players can calculate their contract strategy.
- When a round completes, keep the final trick visible on the felt playing area (`TrickArea` showing `lastCompleteTrick`) with the winner callout, docking the round score summary beneath it so players can review the final trick outcome.
- Reserve full-screen celebratory modals exclusively for final match conclusions (`GameOverOverlay`).
- Modal dialogs and overlays that are used must fit viewports down to 576px height and 375px width with `max-h-[92vh]` and scrollable bodies.
- Decorative accent bars placed at the top of rounded cards must explicitly specify matching rounded top corners (`rounded-t-lg`, `rounded-t-xl`) to prevent subpixel corner clipping artifacts.

### Header & Footer Vertical Conservation
- Never stack multiple sub-header bars above the game table. Consolidate title, round counter, round rules trigger, and trump/contract metadata into the single top navigation bar (`NavBar`) with a collapsible rules drawer.
- Position active turn notifications directly in the focal transition zone between the played trick arena and the player's hand (`● YOUR TURN — PLAY A CARD` with glowing emerald border and animated pulse). Anchor the notification absolutely (`position: absolute -top-10 sm:-top-12 left-1/2 -translate-x-1/2` with zero flow height) to the top seam of the hand container rather than inserting a dynamic block into the flex flow; dynamic flow insertion alters parent flex heights and causes jarring Cumulative Layout Shift (CLS) / screen bouncing every time turns change. Maintain at least 18px of clear vertical buffer (`-top-10 sm:-top-12`) above the hand seam so hovered/playable cards that lift by 18px (`translateY(-18px)`) remain 100% unobstructed, never tucking behind or getting occluded by the callout banner.
- When displaying cut cards establishing trump in the navbar, render a distinct mini playing card badge (solid white background, dark border, rank numeral, and suit-colored pip) rather than plain text.
- Focal play areas (trick arena) must render cards at prominent scale (`size="md"`), never smaller than inactive hand cards. Constrain the player name pill beneath each played card to never exceed the width of the card (`max-w-[64px] sm:max-w-[84px] truncate w-full`) using `getFirstName(name)`. The trick arena container (`TrickArea`) must have a permanently locked, fixed height (`h-[200px] sm:h-[230px] shrink-0 p-3 sm:p-4`) rather than dynamic `min-h` or conditional dimensions based on round state; its height must remain exactly identical whether 0 cards are present, 4 cards are in play, or the collection animation is running. Never use `transition-all` on the table felt container.
- Fixed Card Slots in Trick Arena: Never dynamically re-center a variable-length flex list as cards are played (which causes cards 1, 2, and 3 to slide and jitter horizontally every time a new card lands, causing visual motion sickness). Render a fixed row of $N$ immutable card slots matching the player count (`totalSlots = Math.max(3, Object.keys(playerNames).length)`). Each card lands directly in its permanent slot (`slotIdx`), and empty slots display subtle dashed felt placeholders (`border-2 border-dashed border-emerald-500/20 bg-emerald-950/10`). Existing cards remain 100% stationary throughout the trick. When cards overlap in high player counts (5–7 players or mobile), empty placeholder slots must ALWAYS have `z-index: 0` while played cards have `z-index: 10 + slotIdx`. Empty slots must NEVER render with a higher z-index than played cards, which causes translucent green placeholder boxes and dashed borders to cast artifacts over preceding cards.
- Dynamic Hand Bottom Fill & Centering: The player's hand must measure available container width (`bind:clientWidth={containerWidth}`). When cards fit side-by-side with normal positive spacing, render them with positive gaps and keep them centered (`justify-center`). When cards require overlap (more cards than fit comfortably), compute the exact step (`(availWidth - cardWidth) / (count - 1)`) so the cards fluidly span the full bottom width of the container from small left padding to right padding (8px mobile, 16px desktop) rather than bunching on the left with fixed staircase brackets and leaving a dead void on the right.
- Hand Container Dimension Invariance: When all cards in hand are played (`sorted.length === 0`), the hand container must never shift or bounce (`heightDelta = 0`, `topDelta = 0`). Lock the hand container height permanently to `h-[130px] sm:h-[160px]` (not `min-h`), and give the empty placeholder message (`All cards played`) an exact height matching a real playing card: `h-[94px] sm:h-[122px]`. Set `scrollbar-width: none` on `.card-fan-scroll` so dynamic scrollbar track allocations never cause a 6–8px vertical shift when the hand empties.
- Card Play Launch Animation & Idempotency: When an opponent plays a card, animate it emerging from their top avatar badge (`use:flyInFromBadge`). When the local player plays a card from their hand, capture the clicked card's exact coordinates (`recordPlayedCardPosition`) so it animates gliding upward directly from its slot in the hand onto the felt table over ~420ms. Maintain idempotency via `animatedCardKeys`: cards already on the table must never re-trigger entrance animations when DOM arrays reconcile, ensuring preceding cards remain completely stationary when the final card lands.
- Trick Collection Sequence & Winner Flight: Never use instantaneous DOM replacement or teleportation when collecting completed tricks. The trick collection must animate in two distinct physical phases:
  1. **Deliberate Gathering Phase (700ms)**: After a 500ms landing pause, all played cards glide smoothly inward from their respective slot positions toward the horizontal center of the table (`translate(var(--gather-x), 0px) rotate(var(--gather-rot)) scale(1)` with `cubic-bezier(0.25, 1, 0.5, 1)`), rotating slightly into a tidy physical deck. Cards must strictly retain their chronological lay-down layering (`z-index: 10 + slotIdx`) without z-index jumps or decorative rings. Empty slots and player name tags fade out (250ms).
  2. **Pause & Winner Identification (250ms)**: The gathered stack rests stationary in the center while the winner callout banner displays (`{winnerName} won the trick!`).
  3. **Flight to Winner Phase (750ms)**: The entire gathered stack flies as a cohesive deck: if the local user wins (`winnerId === myId`), animate downward and rightward into the bottom-right corner of the screen into their personal trick pile adjacent to the tricks counter (`[data-tricks-counter]`); if an opponent wins, animate upward directly into that opponent's avatar badge in the seating row (`[data-player-id="${winnerId}"]`). The deck scales down to 0.2 and fades out upon arrival. Ensure both gathering and flying states share identical CSS transform function lists (`translate`, `rotate`, `scale`) for hardware-accelerated matrix interpolation.
- Final Hand & Game Over Transition Flow: In multi-round games (such as Canadian Salad, Oh Well, Rook), when the final card of the final hand is played, NEVER mount the fullscreen `GameOverOverlay` instantaneously. The final hand must execute the exact same physical completion flow as every other hand:
  1. `TrickArea` completes its 2-phase trick collection animation (500ms landing pause, 700ms center gather, 250ms hold with winner banner, 750ms flight into the winner's player badge).
  2. `RoundScoreOverlay` mounts on the table felt, displaying the final hand label (`Hand 7: Salad`), the trick winner callout (`{winnerName} won trick`), the final hand's points, and an action button reading `View Final Standings →`.
  3. Only when `View Final Standings →` is clicked does `GameOverOverlay` mount with the final game podium, full round-by-round breakdown, and `Return to Lobby`.
- Maintain static spatial seating order: Never reshuffle or rotate player pills across tricks; keep players anchored in their fixed table seats (`playerIds`).
- Avatar turn & order indicators: Anchor a unified circular number badge (`1`..`7`) to the top-right of every player's avatar circle. During bidding and trick play, badge `1` must remain permanently locked onto the trick leader (`initialLeaderId` / `lastTrickWinnerId`), NEVER dynamically hopping to whoever is currently bidding or taking a turn (`currentTurnIndex`). Whichever player is actively acting has their own static number badge pulse in glowing emerald (`bg-emerald-400 text-zinc-950 animate-pulse` with ping halo). Avoid duplicate order numbers, "You" badges, or decorative emojis (`👑`, `🎯`, `🤖`) across avatars, pills, and trick labels (`Last Trick: ... | WinnerName`, `Host`, `AI`).
- Turn Indicator Dimension Invariance: When active turn shifts between players, player badges and avatars must maintain 100% invariant layout dimensions (`widthDelta = 0`, `heightDelta = 0`). Lock `border-2` permanently on all badge containers and `border` on all avatar circles so only border color transitions; never toggle between `border` (1px) and `border-2` (2px). Keep font weight locked at `font-bold` for player names without toggling `font-extrabold` (which increases character advance width). Use `transition-colors duration-150` rather than `transition-all` on badges so dimension properties are never animated across layout siblings. Render active highlights via zero-flow outer layers (`shadow-[0_0_12px_rgba(52,211,153,0.3)] ring-1 ring-emerald-400/50`).
- Seating Badge Compact Notation & Width Stability: On mobile viewports and in games with $\ge 6$ players, format player statistics compactly using `${st.tricksTaken}t | ${score}p` (and `${bid} | ${score}p` for Oh Well) with `tabular-nums font-mono`. Truncating `tricks` to `t` and `pts` to `p` cuts stat line width by over 50% (from ~110px to ~45px) and holds badge width stable across score changes. This prevents the staggered 1 - 1 - 2 - 2 wrapping artifact on mobile, allowing 6 players to sit in 2 balanced rows of 3 without reflow or screen bouncing when tricks are won.
- Player display names support up to 20 characters (`MAX_NAME_LENGTH = 20`) to accommodate First and Last names. Avatar circles must compute "FL" initials via `getInitials(name)` (e.g. `John Doe` -> `JD`, `Cason Adams` -> `CA`). In compact table seating strips, format multi-word names as their first name via `getFirstName(name)` (`John Doe` -> `John`) while retaining the full name in tooltip and profile view. Preserve bot identifiers (`Bot Bob` -> `Bot Bob`).
- Button selection groups (such as Table Size and Game Selector) must maintain stable dimensions between selected and unselected states without text wrapping shifts or layout jumps.

## Quality Tooling & CI/CD Pipeline
- **Make Targets**:
  - `make all`: Runs lint (`oxlint`), typecheck (`svelte-check`), complexity (`cccc`), and build (`vite build`).
  - `make lint`: Fast AST linting via `oxlint --deny-warnings`.
  - `make check`: Strict TypeScript and Svelte validation via `svelte-check`.
  - `make complexity`: Cognitive & Cyclomatic complexity enforcement via `cccc web/src` (max-cognitive $\le 20$, max-cyclomatic $\le 20$).
  - `make ripwire`: Code intelligence and symbol ranking via `ripwire web/src --top-k=30`.
- **GitHub Actions (`deploy.yml`)**:
  - Every push to `main` runs `oxlint`, `svelte-check`, `cccc`, and production packaging before publishing to GitHub Pages.

## Git & Version Control Guidelines

### Conventional Commits
- All commit messages must follow the [Conventional Commits](https://www.conventionalcommits.org/) specification: `<type>(<scope>): <description>`.
- Allowed types:
  - `feat`: A new feature or rule addition
  - `fix`: A bug fix or correction
  - `docs`: Documentation changes
  - `style`: Formatting, missing semicolons, etc. (no code change)
  - `refactor`: Refactoring code without changing functionality
  - `perf`: Code change that improves performance
  - `test`: Adding or correcting tests
  - `chore`: Build process, dependency updates, or tool configuration
- The scope should identify the module or game affected (e.g. `spades`, `ui`, `trick-area`, `engine`, `networking`).
- Keep commit descriptions imperative, lowercase, and concise (e.g. `feat(spades): deduct -50/-100 penalty immediately when nil is broken with live toast`).
